# Paired group-bootstrap and multi-seed promotion test

## Summary and mechanism
Treat a challenger as a **paired** alternative to its parent: both models must score the same immutable validation rows, grouped by the same displayed candidate-group ID. For each group, retain every candidate, its label, and both scores. Resample whole groups with replacement; for each resample, recompute the fixed composite, GAUC, and nDCG@5 for both systems, then store challenger-minus-parent deltas. This preserves within-group ranking structure and the pairing, while avoiding the false precision that can arise from resampling correlated candidate rows independently. Cluster-level bootstrap is a standard response to within-cluster dependence, and bootstrap methods have been used for paired retrieval-metric comparisons. ([journals.sagepub.com](https://journals.sagepub.com/doi/pdf/10.1177/1532440011406233?utm_source=openai))

Report the observed delta, percentile 95% confidence interval, and bootstrap win probability `P(delta > 0)`. These quantify uncertainty from the finite validation-group sample, not uncertainty from retraining. Therefore, for seed-sensitive changes, repeat the parent/challenger comparison over a predeclared fixed seed set and promote only when the mean gain clears a practical margin and no protected component metric shows a material regression. Multiple runs matter because a single stochastic training run can be unrepresentative; empirical deep-learning studies document substantial run-to-run variation and brittle conclusions when variation is ignored. ([proceedings.mlr.press](https://proceedings.mlr.press/v227/bosma24a.html?utm_source=openai))

Assumptions: validation groups are the inferential unit or are approximately exchangeable; group membership, labels, candidate eligibility, metric code, and composite weights are frozen; and the two score artifacts align exactly by row key. This is an offline promotion gate, not proof of causal online impact.

## When to use / avoid
**Use** when improvements are small relative to expected group or seed variance; when changing an objective, sequence model, or regularizer with potentially unstable optimization; and when parent and challenger predictions exist for identical frozen candidate groups.

**Avoid** when either artifact is missing, groups cannot be reconstructed reliably, or the comparison also changes data extraction, labels, candidate generation, split membership, or metric definition. In those cases, first restore a common evaluation population; otherwise the paired delta mixes model effect with population shift.

## Requirements and implementation
Required inputs are validation group IDs; immutable row IDs; long-view labels; aligned parent and challenger scores; the exact composite definition; seed IDs; and a recorded bootstrap RNG seed.

1. Run a frozen-candidate-group integrity audit. Require one parent and one challenger score per evaluation row, identical group membership, no duplicate `(group_id, row_id)` pairs, finite scores, and identical label hashes.
2. Compute the point estimate on all groups: composite, GAUC, nDCG@5, and deltas. Define tie handling, group weighting, invalid-group behavior, and whether GAUC is group-averaged before looking at results.
3. Draw `G` group IDs with replacement, where `G` is the number of observed groups. Include all rows for every drawn occurrence, recompute every metric, and repeat.
4. Use an operational default of **2,000** replicates for iteration and **10,000** for the final gate; increase only if interval endpoints or win probability materially change under another deterministic bootstrap seed. These are engineering precision defaults, not universal research thresholds.
5. Store the full bootstrap delta vectors, not only summary statistics. Report the 2.5th/97.5th percentiles and fraction above zero for each metric and composite.
6. For a seed-sensitive change, train both configurations on the same fixed seed set—prefer paired seeds, identical data order where feasible, and identical stopping/checkpoint rules. A practical confirmation default is **5 seeds**; use **3** only as a compute-constrained screening step, not as strong evidence. Aggregate seed-level point deltas by their arithmetic mean. For each seed, retain its group-bootstrap report; do not pool prediction rows across seeds as if they were independent users.
7. Predeclare a practical composite margin `m`, protected-metric floors, and the decision rule. Example: promote only if mean composite delta exceeds `m`, the final paired bootstrap composite interval excludes a practically unacceptable loss, win probability meets the team’s predeclared bar, and mean GAUC and mean nDCG@5 do not violate their regression floors. Choose `m` from decision value, historical metric noise, and online detectability—not from the observed challenger result.

## Starting configuration and expected effects
Start with: frozen validation snapshot; one parent/challenger pair; 10,000 group bootstrap replicates; percentile 95% intervals; deterministic bootstrap seed; five paired training seeds for confirmation; and a written composite margin plus separate GAUC and nDCG@5 guardrails.

A ranking-loss or architecture change can improve GAUC, nDCG@5, both, or neither: GAUC summarizes ordering more broadly, while nDCG@5 emphasizes the head of each candidate list. Do not infer a guaranteed direction or magnitude from the method family. A frequent useful signature is a positive composite driven mainly by nDCG@5 with neutral GAUC, or vice versa; whether that is promotable depends on the predeclared product objective and protected-metric limits. Bootstrap evaluation is suitable for comparing retrieval effectiveness statistics, but it does not remove bias from an unrepresentative validation population or incomplete labels. ([sciencedirect.com](https://www.sciencedirect.com/science/article/pii/S0306457397000277?utm_source=openai))

## Diagnostics and risks
- **Leakage or artifact mismatch:** near-perfect deltas, inexplicable score correlations, missing rows concentrated in one model, or changed label/group hashes. Stop and rebuild artifacts from the same frozen manifest.
- **Wrong resampling unit:** row-level bootstrap often yields implausibly narrow intervals when candidates within a displayed group share context. Resample whole groups; if groups are nested within users or time blocks and dependence is important, define the higher-level unit before evaluation.
- **Few or highly concentrated groups:** a small effective number of groups, one group contributing most positives, or bootstrap draws dominated by giant groups makes percentile intervals unstable. Report group-size and positive-label concentration, then consider a stratified or hierarchical design only if predeclared and implemented consistently.
- **Metric-definition drift:** differing tie rules, top-k eligibility, filtering, or zero-positive-group handling can create false gains. Version and hash metric code and configuration.
- **Seed-only winner:** one seed has a large gain while the remaining seeds are flat or negative. Treat this as optimization sensitivity, not confirmation; inspect learning curves, checkpoints, and seed-level component metrics.
- **Selection bias:** repeatedly trying variants against the same frozen validation set turns intervals into conditional evidence after search. Maintain an experiment log, use the gate only after a hypothesis is predeclared, and reserve a later untouched confirmation set when iteration volume is high.
- **Compute pressure:** bootstrap scoring is cheap once predictions exist; retraining multiple seeds is usually the expensive part. Cache prediction artifacts and per-group metric contributions where mathematically valid, but verify the optimized evaluator against a simple reference implementation.

## Cheapest check and clean experiment
**Cheapest train-only check:** before full confirmation, run one fixed parent/challenger seed with identical training data, schedule, checkpoint selection, and prediction manifest. Execute the integrity audit and a 2,000-replicate paired group bootstrap. If any row alignment, label hash, group reconstruction, or metric-version check fails, do not train further seeds. If the observed delta is clearly below the practical margin or the interval is centered on loss, stop early as a triage decision rather than tuning around noise.

**Clean single-variable experiment:** change only the proposed model configuration—for example, add one regularizer or replace one loss term. Hold architecture except that change, features, candidate generation, data snapshot, temporal split, labels, training budget, optimizer schedule, checkpoint policy, evaluation code, and composite weights fixed. Train parent and challenger using the same five predeclared seeds. Produce one paired bootstrap report per seed and one seed-level promotion table. Do not retune the challenger after seeing this confirmation result; create a new hypothesis and rerun the protocol instead.
